# Release Checklist

发版前必须检查实际 diff 与 Release Notes 是否一致。

---

## 1. 获取差异

```bash
git describe --tags --abbrev=0
git log <上一个tag>..HEAD --oneline
git diff <上一个tag>..HEAD
```

如果没有 tag，则对比主分支或最近一次稳定 commit。

## 2. 检查内容

逐文件检查：

- [ ] 是否有 Release Notes 未提及但实际被修改的模块
- [ ] 是否有已有功能逻辑被替换或删除
- [ ] 是否有配置、依赖、环境变量变化
- [ ] 是否有与本次版本主题无关的改动混入
- [ ] 是否有数据库迁移或数据修正
- [ ] 是否有安全策略变化

## 3. 风险处理

无风险时，可以继续发版。

发现风险时，必须暂停发版并输出：

```text
🚨 发版风险提示

【风险项 1】文件：src/xxx.py
Release Notes 描述：...
实际改动：...
风险：...

请确认以上风险后回复「确认发版」继续，或说明处理方式。
```

用户确认前，禁止继续执行：

- 打 tag
- push
- 部署
- 发布 Release
